# 三个已确认缺陷的物理解读

三个缺陷都针对当前 standard ACE、`ais=OFF`、MGACE fixed-source neutron adjoint 路径。它们不是“核数据天然有问题”，而是核数据、局部密度或粒子类型进入计算时，实际实现没有保持应有物理一致性。

## W5：局部密度没有在伴随权重比中抵消

### 物理对象与正确关系

同一种材料只改变局部原子密度时，散射/裂变产生量与总截面都应乘同一个局部比例 $r$。若采用产生量/总截面形式的伴随权重修正，该公共因子应抵消：

$$w'\propto\frac{r\Sigma_{prod}^\dagger}{r\Sigma_t}=\frac{\Sigma_{prod}^\dagger}{\Sigma_t}.$$

局部密度应影响平均自由程和碰撞位置，但不应额外改变同一材料、同一群、同一反应关系的碰撞权重比。

### 当前偏差与结果影响

RMC 用含 $r$ 的局部密度形成飞行的宏观总截面，但权重分母用未缩放的材料基准总原子密度归一化。因此实际权重变成

$$w'_{code}=\frac{1}{r}w'_{expected}.$$

低密度区域的伴随权重被放大，高密度区域被压低。若这种伴随结果用于重要性或权重窗，会把物理密度变化之外的人工缩放带入空间—能群重要性分布。

### 为什么旧测试没有发现

旧回归和 V4 都固定 $r=1$，此时错误因子恰为 1。V2 只改变 cell `DENS` 为 $r=0.5,1,2$，记录首个碰撞后原生状态，观察到约 $2:1:0.5$ 的权重比例；固定 RNG 重跑哈希一致。

### 证据边界与处理

W5 已由源码与数值确认。它不证明所有混合材料估计器也已完成验证；修复应另立 Stage 3 任务，并以 V2 的密度不变性测试作为回归依据。

## W6：双 nubar 裂变核被无补偿混用

### 物理对象与正确关系

多群裂变伴随核依赖 $\nu\Sigma_f$ 与谱 $\chi$：

$$F^\dagger(h\to g)=\chi(h)\nu\Sigma_f(g).$$

prompt nubar 与 total nubar 描述不同物理定义。究竟采用哪一个是模型选择；但初始化裂变总量、裂变概率、前驱群抽样和权重必须基于**同一个**选择。

### 当前偏差与结果影响

当 `NNUBAR>1`，RMC 初始化和通用 getter 使用第二组 nubar；运行时伴随裂变前驱群却硬编码第一组 nubar。两组与 $\Sigma_f$ 相乘后形成不同核，程序没有施加重要性补偿。

这相当于按一张分布确定裂变产生总量，却按另一张分布决定后继属于哪个能群。增加历史不会让这种不一致自动消失；只会更精确地抽到当前实现定义的混合核。

### 数据与验证边界

部署 `c5g7td` 的两组数据确实不同，故实现不一致成立。该表的概率差很小，V3 的正态近似功效尺度约为 7330 万观测后继；这不是严格样本量保证。第一阶段最小动态输入曾被 W7 阻断；W7 修复后路径已可达，但动态频数、bank 后继和最终响应仍未进行所需高统计量量化。

### 处理原则

不能只机械替换一个 locator。应先决定此 fixed-source adjoint 模型是 prompt-only 还是 total，再让初始化、群抽样、权重及可能的 delayed 处理使用同一个物理核。修复属于 Stage 3。

## W7：纯中子初始化却访问 photon 群

### 物理对象与正确关系

纯中子 MGACE 数据只定义中子能群时，伴随初始化只需要中子上限和中子群结构。不存在 photon 群是合法的核数据状态，不应影响中子伴随计算。

### 修复前偏差与结果影响

RMC 伴随初始化无条件同时定位中子和 photon 最大伴随能量。若数据碰巧带 photon 群，额外访问可只产生无关上限 warning；若数据没有 photon 群，访问空数组会在输运历史开始前崩溃。

V3 的 `c5g7td` 最小输入在第一条 source state 前收到 SIGSEGV，调用栈指向 photon `LocateMgErgGrp()`。这不仅使合法纯中子问题不可运行，也阻断了 W6 的动态裂变验证。

### 修复逻辑：只访问本次计算实际存在的粒子群

伴随初始化需要把用户给定的“最大伴随能量”转换成核数据中的能群位置。转换方法本身没有问题；错误在于旧逻辑默认 neutron 群和 photon 群一定同时存在，因而无论本次计算追踪什么粒子，都连续执行两次转换。

修复后采用两层判断：

1. 只有启用伴随计算时，才处理伴随能量上限。
2. 在伴随计算内部，neutron 与 photon 分别判断：运行模式包含 neutron 才访问 neutron 群结构，包含 photon 才访问 photon 群结构。

| 本次运行包含的粒子 | 定位 neutron 上限 | 定位 photon 上限 |
|---|---:|---:|
| 仅 neutron | 是 | 否 |
| 仅 photon | 否 | 是 |
| neutron + photon（可再含 electron） | 是 | 是 |
| photon + electron | 否 | 是 |

因此，对纯中子问题，逻辑现在等价于：

```text
确认这是伴随计算
	→ 确认运行模式包含 neutron
	→ 用 neutron 群边界定位 neutron 最大伴随能量
	→ 确认运行模式不包含 photon
	→ 跳过 photon 群访问
	→ 继续后续初始化和输运
```

这里的关键不是“为空数组补一个默认 photon 群”，也不是“捕获崩溃后继续”，而是承认纯中子核数据没有 photon 群完全合法，从调用入口消除不应发生的访问。这样既不会掩盖真正的核数据配置错误，也不需要改变底层能群定位函数对合法调用的检查规则。

### 修复没有改变什么

这项修改只决定**是否应访问某类粒子的群结构**。对应粒子确实存在时，最大能量到群号的转换算法、群边界、截面、伴随碰撞核和权重计算均保持原样。因而它恢复的是合法输入的初始化可达性，不是对 W5 密度权重或 W6 裂变核的间接修正，也不能单独证明最终伴随重要性场正确。

### 修复与验证状态

W7 是控制逻辑和数据边界错误，不是输运方程本身的物理模型选择。修复将 neutron 和 photon 上限定位分别限制在实际包含对应粒子的运行模式内，因此 neutron-only 不再访问 photon 群。

同一 `c5g7td` 输入在修复前退出 11、没有 source state；修复后退出 0，完成 10,000 个源历史并记录 12,487 条初始/后继粒子状态。既有 H/O 伴随回归 1/1 通过，reference 哈希不变。该结果确认 W7 的启动崩溃已消除，但不验证 W5/W6，也不等于裂变伴随物理已经正确。

## 为什么局部 V4 通过不矛盾

V4 使用 $r=1$、非裂变 H/O 和带 photon 群数据，在修复前分别避开了 W5、W6 和 W7 的主要触发条件。因此两个群对在当前样本量下未检测到显著差异，与完整能力 E — Defect 完全可以同时成立。W7 现已修复，但 W5/W6 仍足以维持 E 分类。
