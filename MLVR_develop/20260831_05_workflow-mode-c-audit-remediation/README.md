## 2. 调研与设计（② 设计/定位 · Agent 填）

**背景**：20260831_04 新增模式 A/B/C 后，`new_task.sh` 通过搜索任意六列表格分隔行插入台账。现有 `INDEX.md` 的分隔行位于两条任务记录后；该实现会把新任务插到错误位置。首个模式 C 任务也未填 C 模式要求的章节与会话纪要。

**证据链**：
| # | 位置 | 说明 |
|---|---|---|
| 1 | `MLVR_develop/INDEX.md` | 主表头后缺少分隔行，分隔行错置在两条记录之后。 |
| 2 | `MLVR_develop/new_task.sh` | 以任意 `|---|` 行为锚点插入，无法验证该行属于主表头。 |
| 3 | `20260831_04_workflow-multi-mode-upgrade/README.md` | 标为 C/已完成，但缺少 0、2A、6A 和必填会话纪要。 |
| 4 | `MLVR_develop/README.md` | E5 同时混合证据强度、冻结状态、可追溯性和边界质量。 |

**影响面**：影响所有未来建档任务和模式 C 决策的审计性；历史任务内容不迁移或重排，除修正主表格分隔行外不改其结论。

**为什么之前没做/没发现**：首次升级后只验证了新档案生成和模式字段写入，未验证主台账的 Markdown 结构或以模式 C 自身作为完整试运行案例。

## 2A. 物理解释与可证伪假设（模式 C 必填）

**问题定式**：工作流的正确关系为“主表头 → 紧随其后的唯一分隔行 → 最新任务行”。模式 C 的正确关系为“完成状态 → 全部 C 必填产物与人类理解确认可审计”。

**可证伪假设**：若根因判断正确，修复锚点后新任务应总插入主表头分隔行之后；若遗漏 C 产物的检查规则，仍可构造一个标为 C 且缺少人类确认/会话纪要的已完成档案。若未观察到前者，则脚本定位仍不可靠；若观察到后者，则规则仍不足以约束归档。

**物理—代码因果图**：
```text
治理规则：任务顺序与人类理解可审计
  ↓
INDEX 主表头 / 模板决策区 / new_task.sh 插入锚点
  ↓
新任务位置与模式 C 必填字段
  ↓
Markdown 结构检查与隔离建档结果
```

**证据等级**：E2（待完成针对性隔离建档与结构检查后升级至 E3）；治理标签待验证后填写。

## 4. 决策（③ · **人拍板**）

- **采纳方案**：方案 A。
- **决定人 / 日期**：用户 / 2026-08-31（提交审查结论并给出四项验收条件）。
- **理由与约束**：以最小必要改动关闭正式使用阻塞项；人类理解确认须由用户确认或转述后确认，Agent 不得自行替代；不创建额外 Markdown 文档，模式 C 的必要会话纪要例外。

**人类理解确认（模式 C 必填，由人确认或转述后确认）**：
- 我理解本任务要判断/修复的关系是：任务台账的主表头、分隔行和新任务插入位置必须固定对应；模式 C 的已完成状态必须对应完整、可审计的人类理解与结果解释记录。
- 我理解当前根因假设是：脚本搜索任意分隔行而非主表头分隔行，且模板未要求决策者留下自己的理解确认；首个模式 C 档案未经过完整性自检。
- 若该假设错误，预期会看到：修复后新任务仍被插入到非主表头位置，或完整的模式 C 归档仍可在缺少人类确认/会话纪要时通过检查。
- 本次即使验证通过，仍不能推出：未来所有 Agent 会自动高质量填写模式 C，也不证明任何 RMC 物理结论。
- 我批准的范围，以及明确不批准的扩展：批准文档、模板、脚本与任务档案修复；不批准修改 RMC/AIMC、基准、模型、物理结论或执行提交/push。
