## 四、修正问题 2：源权重与归一化分母

原方案将有效起始源权重视为1，并要求分母等于N，但此条件目前校验不充分。

请检查：

- `CDSource::p_dWeight`
- WEIGHT 类型的源分布变量
- FRACTION / BIASFRAC
- distribution sampling 中的权重修正
- source sampling 的最终实际粒子权重
- `CDFixedSource::p_dTotStartWgt` 的真实计算方式

明确区分：

- 用户输入中 `SOURCE WEIGHT=1`；
- 每条实际采样的源历史初始权重等于1；
- RMC 最终用于统计的归一化分母等于N。

这三者不能自动认为等价。

本阶段优先采用**严格限制首版源形式**的方式：

1. 对可能改变有效源权重的 WEIGHT-variable、偏倚/依赖分布和其他不支持的抽样形式，进行显式拒绝，除非能够证明该形式恒保持单位有效初始权重。
2. 在实际源抽样后增加必要的检查方案，验证每条 history 的有效初始权重。
3. receipt记录实际统计分母及必要的起始权重核查信息。
4. 若运行中发现不满足合同的源权重，必须阻止该次运行被标记为成功，不能只因当前代码把分母设成N就认为验证通过。
5. 普通 `CalcFixedSource()` 的历史行为不变。

把受限 source 合同、拟修改的具体函数、运行时拒绝机制及负例测试写入设计和测试计划。

本阶段不扩展到任意权重源的通用统计归一化。

## 五、修正问题 3：每轮统计 FOM 的计时归属

现有 `StatisticsTester::CalcFlucInfluence()` 使用进程级 `OTimer[Total]`，该计时器不能代表单次 prepared run。

请分别明确：

- 进程级 Total 时间；
- 本次 Prepare 时间；
- 本次 Execute/transport 时间；
- 本次 Finalize/tally-processing 时间；
- 当前 StatisticsTester 中依赖进程累计时间的 FOM 数据。

原则：

1. 普通 fixed-source 的计时逻辑不改变。
2. prepared run 必须能够记录本次独立的 Prepare、transport 和 tally finalize 耗时。
3. 后续正式 F11 FOM 以冻结设计约定的本次 MC 时间口径为准：\
   `T_MC = T_prepare + T_transport + T_tally_finalize`。
4. 当前基于进程 Total 的 StatisticsTester 时间/FOM 不得冒充独立 prepared run 的指标。
5. 若 Stage 2 不修改现有 StatisticsTester 的时间计算公式，必须明确将相关累计时间/FOM 标记为非本轮指标，并在比较器中只针对有证据的时间相关字段实施例外。
6. 非时间相关的 tally、RE、统计矩和诊断数据继续严格比较，不能整体跳过 StatisticsTester。

请确定具体实现方案，列出计时边界、拟增加的 receipt 字段、比较规则及需要修改的文件。

不要把 Stage 3 的 TARGET 响应或完整 FOM 评价功能提前开发到本阶段。
