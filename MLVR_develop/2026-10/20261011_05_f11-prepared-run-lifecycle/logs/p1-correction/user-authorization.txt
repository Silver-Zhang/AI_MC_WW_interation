## 四、P1-01：修复 Universe 模型指纹缺失

### 4.1 问题

当前 `src/PrepareFixedSourceRun.cpp` 中的 `definition()` 对 Geometry 进行了部分内容检查，但对：

`geometry.p_vUniverse`

只记录了容器大小，没有完整覆盖 Universe 内部的输运相关信息。

因此，如果两次 half-run 之间，Universe 的填充关系、变换信息等发生变化，但容器大小不变，模型指纹可能无法发现。

### 4.2 修复要求

先读取当前真实源码：

- PrepareFixedSourceRun.cpp
- Geometry/OverviewGeometry.h
- Universe 相关类及实现
- Universe fill、transform、cell membership 和几何定位相关路径

确认哪些 Universe 字段真正参与粒子输运。

然后扩展正式 definition fingerprint，覆盖所有当前支持几何形式中会影响输运结果的 Universe 语义状态。

要求：

1. 不能只添加 Universe 数量或对象地址。
2. 不能直接对整个 C++ 对象做原始内存哈希，因为其中可能包含 padding、指针和临时状态。
3. 应逐字段序列化稳定、确定且具有物理意义的模型定义。
4. 不能把每轮输运会改变的临时缓存加入模型指纹，否则可能造成正常重复运行被错误拒绝。
5. 继续保留现有材料、核数据、cell、surface、tally 和 WW definition 检查。
6. 指纹校验必须在 CLEAR 之前完成。
7. 无法完整验证的几何形式应明确拒绝或保持原有限制，不能默默视为已经受保护。

不允许通过重新加载模型或重复初始化几何来解决这一问题。

### 4.3 必须新增负例

构造具有实际 Universe 填充或变换关系的合法几何模型，不能只修改一个与输运无关的备用字段。

测试：

**U1：正常 Universe 模型**

不修改几何，连续运行至少两次 Forward。

要求：

- 不发生误拒绝；
- 两次运行均与 fresh oracle 一致；
- 指纹在合法换轮过程中稳定。

**U2：Universe 内容被修改**

第一次 Forward 成功后，在测试 driver 中通过正常可访问的模型对象修改一个实际影响输运的 Universe 字段，保持 `p_vUniverse.size()` 不变。

随后请求第二次运行。

要求：

- 在 CLEAR 前发现模型定义变化；
- 不执行新的源历史；
- 不返回成功 receipt；
- 上一次 tally、完成历史数、分母和 RNG 状态保持不变；
- 错误信息能定位到模型定义不一致。

如有必要，再增加一个独立的 fill/transform 变化负例。

测试只能修改用于构造负例的工作模型，不能改生产参考模型或使用私有测试绕过机制。

## 五、P1-02：修复 Native WW 参数验证

### 5.1 问题

现有 `RunPreparedFixedSource()` 会检查：

- WW lower 的正值和有限性；
- lower × WUPN 是否有限；
- lower × WSURVN 是否有限。

但没有完整验证以下参数自身是否合法：

- WUPN
- WSURVN
- MXSPLN

例如，乘积有限并不能证明参数大于零。

### 5.2 修复要求

先检查真实代码：

- ReadWeightWindow.cpp
- WeightWindows.cpp
- WeightWindow.h
- PrepareFixedSourceRun.cpp

明确上述参数在原生 WW 中的物理意义、数据类型、合法范围及相互约束。

**应复用 RMC 原有的合法性规则，不得凭经验随意发明新的数值阈值。**

正式校验至少覆盖：

1. 参数为有限值。
2. 参数满足原有正值、范围及类型要求。
3. 参数之间的关系符合 native WW 合同。
4. lower、survival、upper 的派生结果合法。
5. MXSPLN 不会导致非法 splitting 行为。
6. 任何非法参数都必须在 CLEAR 和输运之前被拒绝。

如果现有 parser 的合法性检查不完整，应在本次 prepared API 边界实现独立完整校验，不改变普通 parser 和 WW 输运数学。

### 5.3 必须新增负例

分别测试：

| 参数 | 负例 |
|---|---|
| WUPN | 0、负值、NaN、Inf、违反原合同的值 |
| WSURVN | 0、负值、NaN、Inf、违反原合同的值 |
| MXSPLN | 0、负值、非法非有限值及违反原合同的值 |
| 参数组合 | 各参数单独合法但组合不合法，或派生三界不合法 |

根据真实参数类型调整不可表示的负例，不能为凑测试而修改其生产数据类型。

**特别注意测试的有效性：**

如果直接在完成第一轮后修改 WW 参数，旧 definition fingerprint 可能先拒绝模型变化。这样的测试不能证明新增的参数合法性检查真正生效。

因此必须增加能够直接验证参数校验的测试：例如在模型绑定前通过测试对象构造非法 WW 参数，或通过正式 owner 校验接口测试其拒绝行为。

不能为了测试而向生产 API 增加私有状态注入开关。

同时测试：

- WW-OFF → WW-ON；
- WW1 → WW2；
- WW-ON → WW-OFF。

确保合法参数不会被误拒绝，实际 native WW 仍然正确产生 lower、survival、upper。
