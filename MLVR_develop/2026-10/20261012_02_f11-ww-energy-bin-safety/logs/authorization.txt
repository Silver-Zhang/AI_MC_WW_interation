## 四、问题 P1-A：能量边界容器索引前验证

### 4.1 当前问题

当前 `src/PrepareFixedSourceRun.cpp:286–288` 中存在：

```cpp
const auto &bins = OWeightWindow.p_vEnergyBins[1];
```

但是访问之前没有确认：

```cpp
p_vEnergyBins.size() > CDParticleState::Neutron
```

随后再检查 `bins.size()` 已经太晚。

类似的问题还存在于：

`src/WeightWindows.cpp:310–312`

的 `InstallPreparedNativeState()` 中。

### 4.2 修复要求

直接阅读以下真实源码：

- `src/PrepareFixedSourceRun.cpp`
- `src/WeightWindows.cpp`
- `src/WeightWindow.h`
- `src/ReadWeightWindow.cpp`

确认每个使用 neutron energy-bin 的位置。

设计一个统一、可复用的验证合同，至少检查：

1. `p_vEnergyBins` 外层存在 neutron 对应的下标。
2. neutron 能量边界内层至少包含两个边界。
3. 边界数值合法，不能出现 NaN 或无效顺序。
4. 能量边界严格递增，不接受重复或降序。
5. 能量区间个数与已安装的 native WW 数据维度一致。
6. `p_vWeightWindowPara` 的外层/内层形状及必要参数也在索引前验证。
7. 不支持的 WW 拓扑必须在输运前拒绝。

特别注意 `ReadWeightWindow.cpp` 会自动追加 `INFINITY_ENERGY` 作为终止边界。

**先定位 `INFINITY_ENERGY` 的实际定义和存储语义，不得简单地将合法终止哨兵当成非法无穷值拒绝。**

如果该常量是有限的大数，按其真实数值合同检查；如果它使用 IEEE 正无穷，则应明确规定只允许出现在末端，而不把它当作有效粒子能量。

建议将验证放在原有 `CDWeightWindow` owner 内，供初始化、运行前检查和安装过程复用。

不得创建第二套独立 WW 数据结构。

### 4.3 调用位置要求

验证必须发生在：

- 初次 prepared model 绑定时；
- 每次 `RunPreparedFixedSource()` 的 CLEAR 之前；
- `InstallPreparedNativeState()` 实际进行中子下标访问之前。

不能只依赖上一层 caller 已经检查。

如果实现一个共享校验方法，应确认所有相关路径都实际调用它，不允许 Run 使用一套规则、Install 使用另一套规则。

WW-OFF 且未声明 native WW 拓扑的合法运行，不应因为要求不存在的中子 WW 能量表而误拒绝。

## 五、问题 P1-B：末端能量边界索引

### 5.1 当前问题

审查指出：

`src/WeightWindows.cpp:45–66`

中的 `setMeshWeightWindowBound()` 调用：

`CDGlobeFun::GetIntpltPos()`

进行能量区间定位。

当前末端回退条件处理的是：

```cpp
erg > bins.back()
```

但当：

```cpp
erg == bins.back()
```

时，可能得到最后一个边界下标，而不是最后一个合法权窗区间下标。

若边界数量为B，合法能量区间索引应为：

`0 ... B-2`

不允许访问 `B-1` 对应的不存在区间。

### 5.2 修复要求

先独立检查：

- `GlobeFun.h` 中 `GetIntpltPos()` 的真实返回语义；
- `WeightWindows.cpp` 中的末端回退逻辑；
- native WW 能量区间的实际存储方式；
- 原始 RMC 对低于首界、恰好等于边界、超过末界的处理约定。

在不改变正常区间内部选择行为的前提下，保证最终索引始终合法。

可以采用最小的区间末端夹取修复，但必须证明：

1. 首界等值定位正确。
2. 内部边界等值遵循原有语义。
3. 末端边界等值映射到最后合法区间。
4. 高于末端时保持既有受支持的回退语义。
5. 无效能量（如 NaN）不会绕过合同进入非法索引。
6. 不改变正常源历史的 RNG 消耗和 WW 物理算法。

**不允许为了修复边界索引而重写 `GetIntpltPos()` 的通用搜索算法。**

如果只需在 native WW 查询结果处进行受控修正，应优先选择最小改动。

注意 `setMeshWeightWindowBound()` 可能被普通 RMC 使用。若修改该共享函数，必须补充普通 native WW 回归，不能仅证明 prepared 测试程序通过。

## 七、必须新增的负例

新增独立的 energy-bin P1 测试，至少覆盖：

| 场景 | 预期 |
|---|---|
| 外层 energy-bin vector 为空 | 索引前受控拒绝 |
| 外层只有一个元素 | 索引前受控拒绝 |
| neutron 内层为空 | 受控拒绝 |
| neutron 内层只有一个边界 | 受控拒绝 |
| neutron 边界重复 | 受控拒绝 |
| neutron 边界降序 | 受控拒绝 |
| 非法 NaN / Inf 边界 | 按真实哨兵合同拒绝非法项 |
| 有效多能群边界 | 可以成功执行 |
| 能量等于第一个边界 | 定位正确 |
| 能量等于内部边界 | 保持既有区间归属语义 |
| 能量等于最后边界 | 只能得到合法末端区间 |
| 能量高于最后边界 | 保持约定的边界处理 |

对非法形状，应同时测试：

**A. 绑定前**

在正常 RMC 输入解析后、prepared 初始化前，利用测试 driver 对 caller-visible WW 容器构造异常状态。

要求在正式生产校验中受控拒绝，而不是发生 SIGSEGV、越界或依赖普通 parser 拒绝。

**B. 首轮成功后**

第一次 Forward 正常完成后，修改 WW energy-bin 容器，再请求第二次运行。

要求：

- 在 CLEAR 前拒绝；
- 不执行第二次 source history；
- 不返回第二次成功 receipt；
- 首次运行的 tally、统计分母和 RNG 不变；
- 错误信息明确指出 energy-bin 形状或数值错误。

注意测试不能只被已有 definition fingerprint 拦截。

**C. 末端等值**

必须实际调用生产 native WW 定位逻辑，观察其结果。

如果正常 MGACE 物理源无法到达 `INFINITY_ENERGY` 哨兵值，可采用受控的 owner/lookup 级边界测试，但必须明确区分它与完整 MC 输运验证。

不能在测试中复制一份区间定位算法代替验证生产函数。
