## 1. 目标与范围（① 立项 · Agent 填）

**要做什么**：解决"工作区文档与历史越积越多 → 每换一次模型/新开对话就要重读一遍 → token 爆炸 + 幻觉"的问题。把"读多少"从习惯变成**有上限的契约**。
**涉及什么**：入口文件（`AGENT_CONTEXT.md`）、6 份长知识库文档的导航头、工作流规范与硬规则；不动任务档案正文、不动 RMC/AIMC 代码。
**怎样算完成**：新会话开场读量从 122 KB 降到 ≈12 KB；入口文件不再随历史增长；同一结论只在一处维护（其余为指针）。
**原始材料**：用户 2026-09-20 提问"换模型/新开对话时上下文越读越多，容易幻觉和烧 token"+ 三项选择（力度中、现在做、速览放 02 矩阵顶部）。

## 2. 做法与证据（② 设计 · ④ 实施 · Agent 填）

**设计 / 定位**（实测数据，2026-09-20）：

| 项 | 体量 | 通读代价 |
|---|---|---|
| 13 个"入口级"文档 | 1759 行 / 122 KB | ≈4–5 万 token |
| 全仓受跟踪 md（含 80 份档案） | 746 KB | ≈25–30 万 token |
| `INDEX.md` | 73 行 / 16 KB，**随任务线性增长** | — |
| `AGENT_CONTEXT.md`（号称"一屏"） | 179 行 / 9.6 KB | 已不是一个屏幕 |
| `AGENTS.md`（每轮自动附加） | 65 行 / 5.3 KB | 每轮固定 ≈2k token |

根因三条：**事实冗余**（同一结论写在 5–7 处，F03 曾因此自相矛盾）、**长文档没有地图**、**默认通读**。
（旁证：`MLVR_develop/2026-08` 本地 8.4 GB 运行产物，但 `.git` 仅 15 MB，未进 git，不构成上下文问题。）

**方案选择**：采纳四层"上下文预算"（用户选定"中"力度）；放弃"轻"（只瘦身入口，冗余未除）与"重"（台账分层 + 自动生成，收益递减）。
- **L0 恒定入口**：`STATUS.md`（已 ≤60 行）+ `AGENT_CONTEXT.md` 179 → 55 行，细节下沉到专题文档与档案。
- **L1 按需取节**：6 份长文档头部加"导航"块（一句话 + 章节行号 + 读法）。
- **L2 单一事实源**：结论类事实只在**任务档案 §4 + `02 审查矩阵`顶部速览**维护，其它文档写指针。
- **L3 交接包**：开场三件套 = `STATUS.md` + `AGENT_CONTEXT.md` + 当前档案 §1/§3/§4。

**实施要点**：
- `AGENT_CONTEXT.md` 重写为骨架 + 指针表（含"到哪读什么"行数预算）；删去与 `01`/`03`/`02` 重复的 Body；
- `00`/`01`/`03`/`06`/`DECISIONS`/`MLVR_develop/README.md` 插入导航头（章节行号随文维护）；
- `MLVR_develop/README.md` 新增 §5e 上下文预算与读法；归档清单加第 8 项（结论变化须同步 02 速览）；
- `AGENTS.md`/`CLAUDE.md` 新增硬规则 12（上下文纪律）。

**验证输出**（2026-09-20 实测）：

```text

# 说明：总量没有大幅下降——本次是把“通读”改成“读图”，导航头本身增了约 40 行。
# 收益体现在“新会话实际读多少”，不在文件总量。

# 3) 交接包（新会话开场真正要读的）
```

|---|---|---|---|

## 4. 结论与边界（⑤ 归档）

- **结论**：工作区有了“上下文预算”契约——恒定入口（≤60 行）+ 长文档导航头 + 单一事实源原则 + 交接包三件套 + 硬规则 12；`AGENT_CONTEXT.md` 从 179 行压到 60 行。
- **验证**：
  ```text
  $ wc -lc MLVR_Knowledge/AGENT_CONTEXT.md
    60  4299     # 原 179 行 / 9638 字节
  $ wc -lc <13 个入口文件> | tail -1

  $ 交接包 = STATUS(6.2 KB) + AGENT_CONTEXT(4.3 KB) + 当前档案 §1/§3/§4 ≈ 4 KB
  ≈ 14–15 KB ≈ 5–6k token（改造前按“通读”约 122 KB ≈ 4–5 万 token）
  $ bash tools/check-archives.sh | tail -1
  汇总: 需处理 1 项（本档案未登记 INDEX）；提示 24 项
  $ diff <(tail -n +2 AGENTS.md) <(tail -n +2 CLAUDE.md) | grep -c '^[0-9]'
  1            # 仅首行互指差异
  ```
  **诚实边界**：入口文件总量只净减 83 行，因为导航头是新增的；本改动的收益在于“每次会话读什么”变了，而不是文件变小了。
- **不能推出什么**（边界）：本改动不减少**已有**文档总量（746 KB 档案仍在），只是让“读多少”可控；也不代表历史档案可信度下降——按需取节时仍以档案 §4 为准。
- **遗留 / 下一步**：
  1. **待落地**：`02_RMC功能审查矩阵.md` 顶部“F## 结论速览”块（内容见下），等并行 Agent 提交 KB02 后再插入；
