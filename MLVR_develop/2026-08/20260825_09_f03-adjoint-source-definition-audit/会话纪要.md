# F03 伴随源定义审查——会话纪要（脱敏）

## 背景

本纪要记录模式 C 设计关口的共识与未决事项，不含原始聊天、凭据或服务器信息。

## 已形成的共识

1. F02 已回答“给定显式源以后，standard MGACE fixed-source neutron adjoint 是否能推进”；F03 不重复审查输运本体。
2. “RMC 能把一个普通外源标记为伴随粒子并执行”不等于“RMC 能从目标响应泛函自动构造正确伴随源”。
3. 当前静态调用链显示：源初态由 `EXTERNALSOURCE/SOURCE/DISTRIBUTION` 或 `SOURCESUB` 提供，之后 `SampleFixSource()` 才设置伴随粒子标志。
4. 当前阶段只读；人工填写主档案第 4 节前不修改 `RMC/`，不更新 benchmark/reference。

## 当前证据支持的判断

- RMC 的通用源可表达位置、方向、能量、粒子类型、cell、时间和权重，并支持偏倚及从属分布。
- Python `SOURCESUB` 可提供更灵活的完整粒子初态，但属于条件接口：需 `USE_PYTHON_API`，且文档限定 Linux。
- 尚未发现 standard fixed-source 路径从 tally/response 对象自动构造伴随源。
- 上述结论目前为 E1 静态证据；尚未执行 F03 专用动态 probe。

## 未决事项（需人工拍板）

1. **已决**：第一版 F03 采用方案 A，允许“人/MLVR 外部控制器负责 response-to-source，RMC 负责执行”；保持 RMC 现有功能，方案 B 暂不采用。
2. **已决**：第一版采用第 1 类探测器 cell 通量/计数型响应，限定为非负、标量、空间×能群响应；反应率和其他响应不纳入本轮。
3. **已决**：接受方案 A 的最小验证范围；cell/群支持域、加权期望、偏倚补偿、MG 群定位和匹配的正向—伴随响应对照均属于失败条件。
4. **已决**：`SOURCESUB` 不进入首版主验证，仅保留为 Linux/`USE_PYTHON_API` 条件下的后续备用接口。
5. **已决**：首版使用 cell 体积积分的 track-length flux；`CELL` 内均匀空间测度，MG 群积分测度不除群宽，各向同性角测度为 $1/(4\pi)$。
6. **已决**：对每个响应分量定义 $H_i=h_iV_i$，RMC 使用 `FRACTION=H_i` 和公共 `WEIGHT=sum(H_i)`；有偏时使用正 `BIASFRAC`，依赖 RMC 的 $F/B$ 初始权重纠偏。
7. **已决**：pilot 为 seed 1、20,000 histories；formal 为 seeds 1/3/5/7/9、每运行 200,000 histories，RNG type 2、stride 1,000,000。支持域、群定位、加权一阶矩、异常扫描和响应级逐 seed/合并 $|z|\le3$ 均为失败停止条件。

## 动态验证构型（运行前冻结）

- 三个等体积同心 H$_2$O cell：内球半径 4 cm，外半径依次为 $4\sqrt[3]{2}$ cm 和 $4\sqrt[3]{3}$ cm；每个 cell 体积为 $4\pi4^3/3$ cm$^3$。
- 正向：cell 1/group 14 单位源；响应为 `(cell 2, group 15, h=0.7)` 与 `(cell 3, group 20, h=1.3)`。
- 伴随：将上述两个响应分量转换为两个源分量，tally cell 1/group 14；正向 CELL 源为源 cell 内均匀单位总强度，故比较 $R_F=0.7VT_{2,15}+1.3VT_{3,20}$ 与 $R_A$。
- 分别验证无偏和固定响应下的 `BIASFRAC` 映射；不修改 RMC、reference 或 benchmark。

## 已完成的人工决策与结果

用户已明确表述目标物理链：把目标探测器的目标计数变成伴随源，经伴随输运评估正向重要性；并批准方案 A、暂不采用方案 B。用户随后选择第 1 类探测器 cell 通量/计数型响应，首版限定为非负、标量、空间×能群。pilot 4/4、formal 20/20 运行成功，源映射和复合响应门槛通过；F03 归档为 **C — Verify（冻结子域）**。通过不外推到反应率、角/表面/时间/符号响应等范围，也不表示 RMC 内建 response-to-source。
