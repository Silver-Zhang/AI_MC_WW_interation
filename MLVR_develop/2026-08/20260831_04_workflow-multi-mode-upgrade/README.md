## 0. 人类阅读摘要（模式 C 必填；A/B 按需）

**要回答的问题**：如何在不降低既有审批和证据要求的前提下，让不同风险的任务采用适当的人类参与深度，并让模式 C 的人能理解所批准结论的因果和边界。

**当前判断与边界**：三模式将参与深度分层，而非授权 Agent 扩大范围。它能规定必要记录和人工确认，但不能自动保证每次解释都正确；首次真实物理模式 C 任务仍需复盘信息密度。

**人需要在什么关口确认理解**：本任务适用工程治理版本的问题定式、因果链、验伪条件和结果解释；用户已在本任务第 4 节的批准中确认采用推荐方案及其边界。

---

## 1. 任务定义（① 立项 · Agent 填）

**目标**：在不削弱既有“证据先行、人拍板、改动留痕”硬规则的前提下，建立 A/B/C 三种任务模式。让人可按风险和学习目标选择参与深度；模式 C 必须把物理问题、代码根因、验证逻辑和结论边界组织成可理解、可证伪的记录。

**范围**：仅修改根工作区工作流文档、任务模板和建档脚本；不修改 `RMC/`、`AIMC_WWiteration/`、基准结果或模型资产。

**验收标准**：工作流规范、模板、建档脚本和 Agent 硬规则一致；脚本能接受可选模式参数并写入任务档案；A/B/C 的选择、升级、人工关口和证据等级有明确且不过度重复的定义。

**原始材料**：无外部报错或实验原始材料；设计依据为本工作区既有五步流程、F02 审查归档经验及用户对“理解每一步”的要求。

## 2A. 物理解释与可证伪假设（模式 C 必填）

**问题定式**：治理目标是把“任务风险与学习目标”映射到相应的人工参与和可审计产物；正确性可观测量是任务档案是否保存了决策、因果解释、验证和结论边界，而非仅有代码 diff。

**可证伪假设**：若三模式设计有效，模式 C 的新档案会同时包含 L0、因果链、人类理解确认、结果解释卡和会话纪要；若任一已完成的模式 C 档案可缺少这些产物，或人仅批准操作而无法说明关系/边界，则该设计未能达到目标。

**物理—代码因果图**：
```text
任务风险与学习目标
	↓
任务模式 A/B/C 与模板字段
	↓
决策、验证和归档记录
	↓
人可复核的因果解释与结论边界
```

**证据等级与治理标签**：E3；已冻结、部分可复现、边界已定义、原始证据已归档。依据为模板/脚本的隔离建档测试与规则文本交叉核对；尚未有真实物理模式 C 任务完成后的效用证据。

## 4. 决策（③ · **人拍板**）

- **采纳方案**：方案 A：A/B/C 三模式、模式 B 默认、风险或物理结论任务默认建议 C；仅对审查/验证结论使用 E0–E4 证据等级与治理标签；不新建独立“能力护照”，在既有任务结论和物理导读中沉淀能力边界。
- **决定人 / 日期**：用户 / 2026-08-31（“请按照你的方案进行工作流的更新”）
- **理由与约束**：目标是加强人的理解与决策，不制造普遍性文书负担；既有 RMC 修改、基准冻结、提交/push 和五步审批硬规则继续有效。

**人类理解确认（模式 C 必填，由人确认或转述后确认）**：
- 我理解本任务要判断/修复的关系是：工作流不应只记录 Agent 做了什么，还必须将任务风险映射到足以让我理解和审计结论的人工关口与档案产物。
- 我理解当前根因假设是：统一五步流程无法区分低风险工程任务和需要物理/统计理解的研究任务，导致“批准”可能不等于“理解”。
- 若该假设错误，预期会看到：仅有五步流程和改动快照也能稳定地让决策者说明正确关系、根因、验伪条件和适用边界。
- 本次即使验证通过，仍不能推出：任意模式 C 文档都会高质量完成，或任何 RMC 物理结论已被证明。
- 我批准的范围，以及明确不批准的扩展：批准工作流、模板、脚本、路线和硬规则更新；不批准修改 RMC/AIMC、基准、模型或物理结论。
