# MLVR 开发总纲与阶段路线

## 项目目标

建立面向 RMC 的基础双向迭代权重窗（Weight Window, WW）框架，用于深穿透 Monte Carlo 问题的自适应减方差。

当前阶段目标不是直接实现高级机器学习算法，而是首先建立稳定、可扩展、方法无关的基础框架。

## 总体路线

```text
Stage 0  工作流与知识库建立
    ↓
Stage 1  双向迭代框架功能需求定义
    ↓
Stage 2  RMC现有功能审查
    ↓
Stage 3  功能缺口修复与补充
    ↓
Stage 4  功能接口分析与框架设计
    ↓
Stage 5  分模块实现并逐项验证
    ↓
Stage 6  基础双向迭代WW框架完成
    ↓
Stage 7  简单场重构方法验证
    ↓
Stage 8  高级机器学习方法扩展
```

## 当前开发原则

1. RMC 是成熟 Monte Carlo 软件，优先复用已有功能。
2. 不重新验证所有已有功能，只重点检查与新框架相关、低频使用或组合后可能存在风险的功能。
3. 先明确方法需求，再检查 RMC 是否满足需求。
4. 不提前设计代码结构，接口设计必须建立在功能审查结果之上。
5. 每连接一个功能，都必须独立验证后再进入下一步。
6. 项目方案由用户逐阶段拍板，Agent 负责调查、证据整理、实现和验证，不自行跨阶段扩展方案。
7. Stage 2 严格执行 `Audit ≠ Repair`；审查发现的问题进入 Stage 3 后另立任务。

### Stage 1 — 双向迭代框架功能需求定义

状态：**第一版需求基线已冻结。**

当前已冻结的核心内容：

- 第一版采用多群 Adjoint transport；
- Field = 空间网格 × 能群上的 mean field + RE；
- Forward/Adjoint Field 规范统一、物理语义分离；
- 第一版固定 iteration 次数；
- 正式 iteration 前设置独立 Bootstrap Stage；
- Bootstrap 第一版采用低粒子数 Analog Forward MC；
- Bootstrap 生成 `WW_A(1)`，不参与正式 FOM、历史场累计或最终物理结果；
- Bootstrap 与正式 iteration 使用相同 Field mesh 和能群结构；
- 第一版不做跨 iteration 历史场累计；
- 第一版 Field Reconstruction 保持方法无关，不绑定高级机器学习算法。

详细定义见：`01_双向迭代基础框架_方法与功能需求.md`。

### Stage 2 — RMC现有功能审查

状态：**已启动。**

统一审查协议见：`03_RMC功能审查规范.md`。

审查原则：

```text
Requirement
  ↓
Existence
  ↓
Actual Behavior
  ↓
Requirement Match
  ↓
Integration Compatibility
  ↓
Targeted Verification
  ↓
Classification
```

结论采用 A–F 六类：Ready / Extend / Verify / Integration issue / Defect / Missing。
